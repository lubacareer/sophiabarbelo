# Model selection and server setup

The public and administrator Vercel projects offer the same fixed model catalog. Both default to Luna. Missing credentials or confirmations disable the affected choice; the server never substitutes another model, including after a rate limit. Changing the next model preserves existing input and results, whose model attribution remains attached to the result. Selections are remembered separately on each origin.

| Picker choice / API ID | Fixed model | Research | Required server configuration |
| --- | --- | --- | --- |
| GPT-6 Luna / `luna` | OpenAI `gpt-6-luna` | OpenAI web search | `OPENAI_API_KEY`, `SOPHIA_OPENAI_COSTS_CONFIRMED=true` |
| Gemini 3.8 Flash / `gemini-3.8-flash` | Google `gemini-3.8-flash` | Tavily | `GEMINI_API_KEY`, either `SOPHIA_GEMINI_FREE_CONFIRMED=true` or `SOPHIA_GEMINI_COSTS_CONFIRMED=true`, plus Tavily below |
| GLM-4.7-Flash / `glm-4.7-flash` | Cloudflare `@cf/zai-org/glm-4.7-flash` | Tavily | `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, `SOPHIA_CLOUDFLARE_FREE_CONFIRMED=true`, plus Tavily below |
| Grok 4.7 / `grok-4.7` | xAI `grok-4.7` | xAI web search | `XAI_API_KEY`; public additionally requires `SOPHIA_PUBLIC_XAI_COSTS_CONFIRMED=true` |

Both Tavily-backed choices require `TAVILY_API_KEY` and `SOPHIA_TAVILY_FREE_CONFIRMED=true`. API keys and tokens are Secrets, never `VITE_*` variables. Account IDs and confirmation flags are server-side configuration. Keep administrator deployment protection enabled. Public Grok uses fixed low effort; only administrator Grok exposes the reasoning-depth selector.

## Verify access and billing before enabling it

- **Gemini:** create an API key in an unbilled project shown as Free Tier in AI Studio. Google AI Ultra increases AI Studio interface limits, but direct API billing is separate; eligible Cloud credit benefits are also separate from free-tier access. This adapter uses Gemini's REST Interactions API with `store:false` and no native Google Search tool. [Model capabilities](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash), [pricing](https://ai.google.dev/gemini-api/docs/pricing), [subscription benefits](https://ai.google.dev/gemini-api/docs/google-ai-plans).
- **Gemini with API credits:** for a billed project, keep `SOPHIA_GEMINI_FREE_CONFIRMED=false` and set `SOPHIA_GEMINI_COSTS_CONFIRMED=true` only after authorizing API spending in that Vercel project. This opt-in applies equally to public visitor requests and administrator requests; configure each project separately. Eligible Ultra/Developer Program Cloud credits can offset usage, after which paid funds can be consumed. The picker displays API credits whenever this paid opt-in is true, including if the free flag is also true. With neither confirmation it remains disabled and labeled API credits. No balance, billing identifier, or key is exposed. This is a cost authorization, not a guarantee that an API request will succeed or that usage is free. [Gemini billing](https://ai.google.dev/gemini-api/docs/billing).
- **Cloudflare:** verify the selected account uses Workers Free and create a token scoped to that account's Workers AI Read/Edit permissions. Use the direct Workers AI endpoint, without a paid AI Gateway route. The free allocation is 10,000 neurons per day; a Workers Paid account can bill overages. [Model](https://developers.cloudflare.com/workers-ai/models/glm-4.7-flash/), [pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/).
- **Tavily:** verify Researcher, PAYGO off, and remaining credits. Use a Development key; Tavily's Production key category requires a paid plan or PAYGO and is distinct from Vercel's Production environment. Researcher provides 1,000 monthly credits, and advanced search uses two credits per query. [Credits](https://docs.tavily.com/documentation/api-credits), [key limits](https://docs.tavily.com/documentation/rate-limits).

Confirmations attest that these checks were completed; they do not monitor later account billing changes. Recheck them if provider plans or projects change. The Gemini API-credit opt-in never changes Google billing or auto-reload settings. Both Gemini modes still require Tavily's verified free allowance. Exhausted free access returns an error rather than enabling billing, upgrading a plan, returning an unresearched answer, or switching providers.

## Research bounds and citations

The new Gemini and GLM paths use the selected model to plan one to three distinct queries, each at most 400 characters. Tavily runs advanced searches with up to five results per query. The same selected model then analyzes the original passage and up to 30,000 characters of research. Query generation is capped at 2,048 output tokens and final analysis at 8,192, with a shared 240-second research cap and no automatic retries. A full three-query run uses up to six Tavily credits; the two paths and both domains share the account's allowance.

Both deployed roles also share a 280-second application work budget, beginning at the analysis handler before quota acquisition and URL extraction. Extraction and every selected provider use the same deadline; research receives at most 240 seconds or the remaining request time, whichever is shorter. Expiry stops awaiting DNS resolution and cancels article and provider I/O, including connections and response-body reads; no further address attempt or redirect starts. An active DNS lookup may complete later, but its result is ignored. Timeout responses use a localized HTTP 504, and admitted timeouts still count toward public quotas. Lease release keeps its independent five-second store timeout after cancelled work settles. The 300-second Vercel function limit and 330-second public lease remain unchanged; the application budget leaves headroom for cleanup, response handling, and platform overhead. Local/Caddy requests retain their existing provider-specific limits.

GLM's query and analysis calls can use the remaining shared research budget, capped at 240 seconds, rather than each stopping at an earlier 120-second cutoff. Their combined research budget is still 240 seconds, not 240 seconds per stage. Other inference calls retain their existing 120-second cap and Tavily retains 30 seconds per search. A confirmed inference-call timeout returns the localized HTTP 504 instead of a generic connection error; a Tavily call timeout remains a research-unavailable error. Safe server diagnostics distinguish request stage, fetch/body phase, timeout/cancellation/transport category, elapsed time, and allowlisted transport codes without logging submitted text, credentials, account IDs, full URLs, error messages/stacks, or response bodies. No retries or billing upgrades are enabled.

Only safe URLs reported in Tavily results enter the citation allowlist. The existing validator preserves exact source excerpts, removes invented links, and leaves unsupported factual conclusions unverified. It cannot prove that a listed source supports every explanation. Source text and search results remain untrusted material rather than model instructions. Luna retains its existing independent passage-analysis pipeline; Grok retains its existing xAI research pipeline.

All public models share the same Redis quota identifiers: five admitted attempts per ten-minute window, thirty per twenty-four-hour window, two concurrent analyses per client, and three across the public site. A model change grants no additional allowance. Configuration and selection errors are rejected before admission; provider and extraction failures after admission still count. Administrator analyses bypass those application limits.

## API compatibility

`GET /api/config` adds `models` and `defaultModelId`. Each record contains its fixed `id`, `label`, `available`, `unavailableReason`, `access`, and `reasoningControls`; it contains no key, token, balance, or billing identifier. `POST /api/analyze` accepts optional `modelId`, and successful deployed responses include `analysisModelId`. Omitting a deployed selection now selects Luna on either role. Unknown, unavailable, or incompatible selections fail before quota acquisition or URL extraction.

The deployment role is server-owned. Request headers, browser pathnames, arbitrary provider names, and raw model names cannot select another role or endpoint. Public Grok rejects supplied reasoning overrides. Existing local/Caddy behavior remains selected by `ANALYSIS_PROVIDER`; its legacy config response does not expose the deployed picker, and explicit deployed `modelId` requests are rejected locally. The local Groq adapter remains available for compatibility. Deployed `SOPHIA_PUBLIC_PROVIDER` and Groq fallback settings are ignored by this version.

## Preview and Production setup

1. Verify provider account tiers and create durable application credentials. Do not reuse revoked or expiring benchmark credentials.
2. Add Secrets separately to each project's Preview environment, scoped to `codex/public-research-quotas`. Add only confirmations backed by completed access checks. Keep the administrator deployment protected and public-project previews protected.
3. Push the branch to create ordinary Git-triggered previews. Verify configuration, selected-model attribution, citations, quota sharing, and administrator authentication before staging Production values.
4. Stage the verified new Production variables without altering existing live provider settings. Retain old Groq variables temporarily for rollback compatibility; new code does not call them. Environment changes take effect only in a new deployment.
5. Leave merging to the maintainer. Do not change billing, remove protection, or manually redeploy as part of credential setup.

Submitted text goes to the selected model provider. Tavily-backed models also send generated queries, which can contain submitted text, to Tavily, and receive its research results. Review the applicable providers' terms and data policies, especially the free-tier data-use terms. Neither a consumer subscription nor an app confirmation flag guarantees an unlimited or free production API allowance.
